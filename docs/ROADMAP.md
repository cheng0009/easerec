> 产品定位: **录屏即成片** —— 一次录制，直接产出可发布视频，不做后期。
> ✅ = 已实现（含单元测试）；未标记 = 未开始。

## P0 基础设施：统一剪辑决策列表（EDL） ✅

所有"录后处理"功能（倒带、隐私剪除、快进、片头片尾）共用同一套数据结构，这是后续一切的地基。

- **存储**: 与录像文件同目录的 sidecar 文件 `xxx.webm.edits.json`，录制中实时追加写入（同时兼做崩溃恢复的元数据源）。
- **录像增量落盘**: MediaRecorder chunk 到达即追加写入 `.webm` 文件（首块含头，后续块追加仍为合法流式 WebM）——隐私内容回溯扫描与崩溃恢复的共同前提，同时使录制内存占用有界。
- **Schema（草案）**:

```jsonc
{
  "version": 1,
  "durationMs": 1234567,          // 录制总时长（墙钟）
  "edits": [
    { "type": "cut",    "startMs": 61000, "endMs": 64500,
      "reason": "rewind" | "privacy" | "pause", "label": "" },
    { "type": "speedup","startMs": 120000, "endMs": 185000,
      "targetSecs": [3, 5], "audio": "mute" | "whoosh" },
    { "type": "mask",   "startMs": 200000, "endMs": 214000,
      "region": { "x": 0.62, "y": 0.03, "w": 0.3, "h": 0.08 },  // 归一化
      "style": "black" | "blur", "muteAudio": false }
  ]
}
```

- **导出器**: 新的导出编排器按 EDL 生成 ffmpeg 步骤（分段处理 + concat），取代现在单条 ffmpeg 命令的 `runExport`。处理顺序固定：EDL 剪辑/变速 → ASR+字幕 → 烧录 → 响度归一 → 片头片尾拼接。
- **时间轴 UI**: Timeline 组件可视化全部标记，支持导出前微调边界（尤其隐私标记的 start 往前扩）。

## P0 倒带 / 隐私剪除（同一机制，双语义） ✅

**方案：导出时剪辑（编辑列表方案 A）** —— 录制引擎零改动。按键只写 EDL 记录，导出时 ffmpeg 删区间。对用户的最终结果与"真倒带"完全一致，且误按可在时间轴上撤销。

- **口误重录语义**（F2/F3）: 单键触发"从 now-N 秒 到 now 剪掉"，N 默认 3/5 秒。连续按压产生连续区间，导出时合并。
- **局部遮挡（主流程，F6）**: 适用"屏幕局部有敏感信息、演示继续"的场景。
  - 按 F6 → 覆盖层进入框选模式，拖拽画出遮挡矩形（复用标注交互）→ 黑框**实时**画在覆盖层上并被录进素材，从按下瞬间起画面即安全；框不吞鼠标，遮挡区域下可继续操作。
  - 同时写入 mask 型 EDL 记录：**startMs 由内容回溯自动定位**（见下），endMs = 移除框的时刻（再按 F6）。
  - **自动回溯（默认行为，替代估算时间）**: 遮挡动作本身就声明了"该区域当前内容 = 隐私内容"。按下 F6 画框确认时，采样**双重参照**——遮挡区域裁剪 + 整屏上下文（敏感信息总是随某个页面/窗口打开而出现，整屏状态是强锚点）。后台以约 2fps 回扫已落盘录像，逐帧同时计算区域相似度与整屏相似度（感知哈希；阈值取"页面级差异可辨、光标/时钟/动效噪声可忍"），取**最早同时满足两个条件**的帧为 startMs——即"这块内容出现在这张页面里"的首次时刻。整屏比对否决"早前别的窗口恰好相似"的误锚，区域比对捕捉"页面早已打开、内容刚出现"的小变化，互为盲区补充。完成后反馈"已回溯到 MM:SS"；内容自录制开头就存在则起点为 0。遮罩自首现时刻**连续到底**（中间消失时段也遮，黑框盖空角落无害）。
  - **回退阶梯**: ① 区域+整屏联合匹配（默认）→ ② 整屏弱化为区域外扩邻域（多显示器/大面积动效干扰整屏哈希时）+ 区域联合 → ③ 仅区域匹配（标"待人工复核"）→ ④ 固定宽限窗（默认 8 秒，可设置）。时间轴始终可手动拖动起点。
  - 导出时对整段区间做同区域遮罩（黑条/模糊可选）——与实况黑框同区域同视觉，衔接无缝；时间线不断、解说不断。
- **整段剪除（辅助，Shift+F6）**: 仅适用全屏私密活动（登录、输密码、打开私人应用）——可预判，先按再动手。开/关式区间标记，导出时整段剪掉；零散小段回剪用 F2/F3。
- **配套**:
  - 标记激活时在**不被采集的表面**（主窗口状态栏 / 迷你窗）显示提示；遮挡框是唯一上屏元素。
  - **导出前隐私复核（安全网）**: 时间轴列出全部隐私标记，点击跳转预览、可拖动边界——回溯已自动定位起点，复核做的是确认与微调。
  - 导出报告: "已遮罩 N 处、剪除 M 段共 X 秒"。
  - 远期: 离线 OCR 回溯的语义级增强——内容哈希只能定位"同一画面"，OCR 可识别"同类模式"（敏感信息变换形态后再次出现），在哈希匹配不可靠时兜底（离线无延迟压力，比实时检测可行）。
- **远期升级（方案 C）**: WebCodecs 自研编码管线（VideoEncoder + muxer，短 GOP + 内存 Ring Buffer），实现录制时真丢弃 + 原生 H.264/MP4 + 导出免转码。独立立项，不阻塞本功能。

## P0 快进模式（F4） ✅

- **录制时**: F4 开/关，向 EDL 写 `speedup` 区间；覆盖层渲染 30% 黑遮罩 + 角落"⏩ 快进中"图标 + 中央提示"视频快进中..."（此特效**要**被录进素材，与特效哲学一致）；音频轨 `enabled=false` 实时静音。
- **导出时**: 区间强制压缩至 3–5 秒（`setpts` + 分段重编码），音频替换为低音量 whoosh 音效（预生成素材随应用打包）。
- **联动**: 快进期间冻结 SmartZoom/弹簧相机，避免加速画面中镜头乱晃。
- 默认热键 F4（未被占用），可在 shortcuts.json 自定义。

## P1 字幕管线（本地 ASR + 在线 LLM 校正） ✅

1. **流程顺序（关键）**: EDL 剪辑 **之后** 才做识别——保证时间戳与成片对齐，且少识别被剪掉的部分。
2. **本地识别**: whisper.cpp CLI（`whisper-cli.exe`）主进程 spawn，与 ffmpeg 同模式；不引入 Python。模型 ggml base/small/medium 放设置档位，从 hf-mirror.com 下载到 appData（镜像感知）。
3. **LLM 校正**: 按 ~40 段一批发送 `{id, text}`，提示词严禁增删合并段落，**时间戳永不交给 LLM**；返回校验 id 一致，失败整批回退原文。OpenAI 兼容接口（baseURL/key/model 可配，适配 DeepSeek/GLM/Qwen）。总开关可关（纯本地、不联网）。
4. **字幕样式**: 生成 **ASS**（非 SRT）烧录；设置面板新增字体、字号、颜色/描边、垂直位置+边距设置项，存 settings.json。注意 Windows 下 ass 滤镜路径冒号转义（用相对路径 + cwd 规避）。
5. **长段拆分**: whisper 段落按标点 + 最大字符数/最短时长拆成字幕粒度。

## 智能跟焦架构升级（2026-09-08 第二批）✅

**录轨迹，导出渲染**（用户确认的核心卖点架构）：
- 录制端零变换：画面恒为 1:1 全幅（根除跟焦导致的编码压力/回放卡顿）；仅记录鼠标轨迹（~30ms 节流，去重）流式写入 `xxx.mouse.jsonl` sidecar。
- 导出端离线重放：`focusZoom.ts` 用与实时完全相同的 SmartZoom + SpringCamera 重放轨迹（真实采样间隔为 dt），拐点容差下采样为关键帧，编译成分段线性插值的 ffmpeg `zoompan` filtergraph（帧计数器 `on/fps` 驱动 z/x/y）。
- 捆绑 ffmpeg 无 `-filter_complex_script`：graph 直传 argv，超过 26K 字符预算时按关键帧窗口自动分段渲染 + concat 拼接（接缝相机值连续）。
- focus pass 位于 EDL 剪辑之前（时间轴与原始素材 1:1 对齐）；竖版 9:16 同样改用相机重放序列取景。
- 预览区叠加蓝色虚线"导出时放大此区域"框（实时弹簧模拟驱动，绘制不进录制流）。
- 设置：智能跟焦默认开启（零负担），放大倍率 1.2/1.5/2 可选。
- 测试：15 个 focusZoom 单测 + 2 个真实 ffmpeg 集成用例（端到端渲染、与 EDL 叠加），全套 137 测试通过。

## 导出画质与跟焦修复（2026-09-08 第三批）✅

用户实测反馈"导出卡顿 + 无跟焦"的诊断与修复：
- **卡顿（实为块状失真）**: libopenh264 未显式设码率，默认 ~2 Mbps，屏幕内容+跟焦大运动下满屏块状 → 感知为卡顿。新增 `bitrateFor(w,h)`（1080p→12M / 1440p→21M / 4K→40M 封顶），`encArgs()` 统一带 -b:v/-maxrate/-bufsize 贯穿所有编码 stage。实测 2 Mbps → 11.6 Mbps。
- **无跟焦**: 上一轮"实验性默认关"时代的 zoomEnabled:false 被持久化并覆盖新默认 → 存储键升级（localStorage v3 / 主进程 app_settings_v2），跟焦默认开启生效。
- **旧录像无轨迹**: 导出时开启跟焦但无 mouse.jsonl → 结果明确提示"该录像没有鼠标轨迹，未渲染智能跟焦"。
- 诊断方法：合成轨迹 + 真实 ffmpeg 渲染 + 流探测（CFR/时长正确）+ 双帧边缘密度比对（1.35 ≈ 1.5× 放大特征）确认渲染管线本身无误，问题全部在参数与持久化层。

## 高亮笔连续性与跟手重做（2026-09-08 第四批）✅

确认原设计为**故意不连续**（代码注释 "INDEPENDENT strokes, never connected"——每次按下=独立笔画模拟抬笔）。用户要求连续 + 跟手，重做为流式墨迹架构：
- **增量直推**：每个笔迹点采样即发（ov-pen: down/pt/up/clear/trim 轻量事件，主进程转发），不再随 33ms 整帧批量推送、不再全量序列化笔画（原实现每帧深拷贝全部点过 IPC，越画越卡）。
- **覆盖层本地绘制 + 60Hz 实时延伸**：笔画累积在 overlay 本地；鼠标事件（60Hz）驱动重绘"最后已知点→当前光标"的活动段——笔迹与光标同步，消除 30fps 追 60Hz 的半拍滞后。
- **连续墨迹**：新笔画与上一笔画末端自动桥接（跨松手/按下连续），模式关闭/清理时墨迹同步清除；超量墨迹 trim 丢最旧笔画。
- 附带优化：逐点颜色采样的 1x1 canvas 预分配（原每点重设尺寸）。

## 品牌片尾（2026-09-08 第五批）✅

导出抽屉新增「附加品牌片尾」开关（默认开）：导出时用 ffmpeg lavfi **动态生成** 2.8s 品牌卡（深色背景 + "简录 EaseRec" 主标 + Slogan 淡入淡出 + 静音双声道），无预制资源文件；字体自动探测（msyh→simhei→segoeui），文案跟随界面语言；拼接顺序恒为 主片 → 用户片尾 → 品牌卡。

## 长视频跟焦渲染修复（2026-09-09）

用户实测：导出报错 "render follow-focus (zoompan) part 1/2 - Could not open encoder (EINVAL), frame=0"。

**诊断过程**（导出失败时转储完整命令行 + 二分实验）：
- 命令行长度（19k chars < 32K）与参数合法性排除；
- 常量表达式成功、动态表达式失败 -> 表达式求值问题；
- 初判"嵌套深度"（>60 层 if 失败）改为平铺 clip/gte 形式后仍失败（零嵌套也炸）；
- 进一步二分锁定真正根因：**本 ffmpeg build 的 zoompan 表达式求值器在单表达式超过 ~100 个运算符/词元时内存分配失败**（"Cannot allocate memory" -> Error reinitializing filters），与嵌套无关，纯常量求和 101 项即失败、100 项稳定通过；clip 项约 90 个为上限。

**修复**：focus pass 按关键帧窗口切分渲染时，每窗口关键帧预算从"按字符数估算"改为**固定 40 个**（<=39 个 clip 项 ~= 2.6k 字符，实测余量 ~45%），窗口重叠 1 关键帧保证接缝相机值连续，段间 concat 拼接。25s 长视频复现用例（多窗口）验证通过。

**注意**：多窗口渲染为全尺寸重编码，长视频导出耗时随窗口数线性增加——正确性优先的取舍；后续可引入硬件编码或更激进的相机曲线压缩来降低窗口数。

## 智能缩放重构：借用 Recordly 的 ZoomRegion 模型（2026-09-09 第七批）

用户反馈导出慢、缩放一帧一帧卡顿、屏幕两侧无跟焦。对照 Recordly 源码发现根本设计差异：Recordly **不做逐帧连续跟焦**，而是 `ZoomRegion`（startMs/endMs/depth/focus）——检测"在哪里停留操作"，切出**静态焦点**的缩放段，进出各 ~400ms 弹簧缓动。段内相机完全静止，因此天然丝滑；渲染只是固定裁剪，极快。

重构内容：
- 新增 `zoomRegions.ts`（纯函数 + 7 单测）：dwell 聚类（质心跟踪、半径 8% 宽度、≥500ms）→ 区域（lead-in 250ms / hold 400ms / merge 限同址 / min 1200ms）→ `buildFocusSpans` 展开为全时间线覆盖的 ease/hold/ease 渲染段。
- 修复轨迹采样：采样移入 60fps 合成循环（原实现依赖鼠标移动事件，停留期轨迹空洞 → 回放漂移），停留每 400ms 打点，推拉平滑。
- 修复 4K 两侧无跟焦：SmartZoom `teleportPx`/`deadZonePx` 按源宽度缩放（原 900px 按 1080p 写死，4K 下正常快速甩鼠标被误判为瞬移）。
- 渲染管线替换：zoompan 巨型表达式（求值器 ~100 词元上限 + 抖动）与 Chromium 逐帧渲染实验全部移除；改为每 span 固定 crop+scale（hold 段零抖动），进出缓动用 zoompan 短表达式（12 帧）；段间 demuxer 流拷贝拼接。crop 动态宽高会使编码器 EINVAL，故 ease 段用 zoompan（输出尺寸恒定）——混合策略实测通过。
- 真实 ffmpeg 集成：20s 素材含轨迹渲染 7.5s 完成（约 2.7x 实时），时长精确，与 EDL 剪辑叠加正常。151 测试全过。

## 录制端根因修复 + 聚类锚点制（2026-09-09 第八批）

用户仍报卡顿。对导出文件的帧序诊断揭示**真正根因在录制端**：源录像 51.8s 但 45s 后无帧可解、相隔 20s 的两帧差异仅 1.8/255（画面冻结）。链路是：录制开始后主窗口最小化 -> rAF 在隐藏窗口停止触发 -> 合成画布停绘 -> captureStream 无帧 -> 录出来的是幻灯片。任何导出优化都无法挽救烂素材。

修复（完全照搬 Recordly 的"录制热路径无画布"原则）：
- **原生轨直录**：无摄像头时 MediaRecorder 直接录 getDisplayMedia 的原始视频轨（画布彻底退出热路径），有摄像头才走画布合成。
- **30ms 录制节拍器**：替换 rAF 驱动鼠标采样（及摄像头模式下的画布绘制），最小化下照常工作。实测同脚本下轨迹从 42 点 -> 1600+ 点。
- **硬件编码**：MediaRecorder 优先 `codecs=h264`（映射平台硬件编码器），替代软件 VP9（CPU 饥渴导致丢帧）。
- 实测录像健康：h264 流、全时间线抽帧内容正确（操作时差异 3.0+，静止时 0.0）。

**导出端连带修复**：
- 未收尾 webm 的重封装改为 **MP4 容器**（h264-in-webm 无法回封 webm，MP4 可写索引与时长）——解决了崩溃恢复/异常停止录像 seek 全空、span 渲 0 帧的连锁问题。
- dwell 聚类改**锚点制**：原运行质心会"橡皮筋"漂移，把几分钟自然使用粘成一个巨大区域；现以停留起点为锚，离锚即断。
- E2E 真实素材（4K/60s/3200 轨迹点）导出验证通过；30s 截取内单 dwell 场景 spans 展开正确（ease/hold/ease）。
